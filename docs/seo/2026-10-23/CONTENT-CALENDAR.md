# 90-day content calendar

Day 0 means the approved publication date; none is scheduled by this document. Founder owns publication and product claims. Engineering owns the generator, checks and source/release parity. Editorial owner is Kapisch Bhardwaj.

| Window | Work | Evidence required before publication | Decision signal |
|---|---|---|---|
| Initial package | Six guides and hub, product/Journal links | Source-checked capabilities, current competitor references, passing site checks | Seven complete useful routes |
| Days 1–14 | Search Console/Bing URL inspection; rectify technical issues | Actual owner account data | Discoverable URLs and actionable coverage errors |
| Days 15–28 | Real workflow film; app/version support page if tested | Synthetic cross-app run, explicit failures and OS/build identifiers | Repeatable delivery in each named app |
| Days 29–42 | Improve highest-impression task guide; draft German equivalent | Actual query export and native editorial review | Useful relevant impressions/support demand, not volume guesses |
| Days 43–56 | Paired German publication if justified | Meaning/register review, reciprocal hreflang, 375px checks | Localization quality and actual demand |
| Days 57–70 | Easy Write vs one close alternative, only if independently tested | Fair repeatable methodology and current vendor facts | A decision readers cannot make from feature lists alone |
| Days 71–90 | Publish one evidence-led case study or deeper guide; consolidate overlaps | Consented user evidence or synthetic study clearly labeled | Useful new evidence, not page-count quota |

Backlog: local glossary workflows; bilingual email review; troubleshooting unavailable Apple model; privacy of clipboard/history; read-only selection versus future OCR. Do not ship an OCR/screen-translation guide as an available feature. No testimonial or “helped X people” article until genuine permissioned evidence exists.
