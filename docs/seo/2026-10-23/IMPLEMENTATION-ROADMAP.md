# Implementation and release roadmap

## Local content package

- Research corpus, qualitative query map, competitor matrix and claim rules.
- Six finished guide drafts; static hub/detail renderer integrated with the existing website generator.
- Product and Journal discovery links; truthful structured data and dates; unchanged training-crawler policy.
- Build/lint/type-check, release regressions, static links/metadata and 375px/desktop browser checks.
- Reviewable local output and a scoped semantic commit that excludes pre-existing work.

## Website publication gate

Owner approves the concrete artifact. Recheck the actual public release and vendor comparisons. Integrate scoped changes into the website's intended release branch, preserving other active work. Deployment, push and merge are separate owner-authorized actions. Verify HTTP responses, canonical links, sitemap and release parity after any authorized publication.

## Native release dependency

The website package does not complete app release acceptance. The native repository still lists physical cross-app, VoiceOver, notarization and signed-update gates. Keep source-only/preview language until those are actually cleared and the distribution exists. A misleading download promise would harm reader trust and acquisition quality.

## Growth operating loop

Owner-provided Search Console/Bing exports → page/query diagnosis → one specific improvement → verify and approve → observe enough data to decide. Do not promise revenue, traffic, rankings, AI citations or full market coverage from this research.
